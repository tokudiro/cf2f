# cf2f 仕様・設計方針

このドキュメントは、cf2f の設計方針と現在の仕様をまとめたものです。
「決定」は作者が決めた方針、「未決」はまだ決めていない点です。

## 目的

C言語のソースコードから、関数の呼び出し関係(コールツリー)を取り出して Graphviz で可視化する。

世の中のツールには、include ファイルがないと解析できないものが多い。
cf2f は、**include ファイルがなくても使える**ことを原点として作った。

## 設計方針

### 決定

- **字句解析(flex)だけで動かす。** 構文解析も、ヘッダの解決も、前処理もしない。
  - 型名は(ヘッダの型を含む)一覧を持たず、字句のパターンで判定する(例: `MyType t` は、単語が2つ並ぶ形から変数宣言と判断する)。
  - `gcc -E`、libclang、ctags などで前処理や型解決をする方向には広げない。
  - その代わり、完全な正確さは目指さない。ヒューリスティックで十分な精度を狙う。
- **ソート・重複除去は外部コマンドに任せる。** 出力に同じ行が複数出てもよい。cf2f、funclist、cf2v のすべてに当てはまる。
  - README の例のように `sort | uniq` を通して使う。
  - ツール側に重複除去や整列を持たせない。
- **cf2v は、関数内に宣言がない変数を局所外とみなす。** 引数と、波括弧のスコープごとの局所変数を宣言として覚え、それ以外の単語を変数の使用とする。
  - 呼び出し(後ろが `(`)、キーワード、`.` / `->` の後ろのメンバ名、ラベル、`goto` の行き先は変数に数えない。
  - すべて大文字の名前はマクロや定数とみなし、出力しない。
  - 型名の一覧は持たない。ただし、このファイルの `typedef` で定義された名前だけは覚え、宣言の始まりの判定に使う。ヘッダの型は見えない。
  - 宣言のない単語には、ヘッダの変数、マクロ、`enum` の定数が混ざる。完全な正確さは目指さない。
- **cf2v と cf2f の出力は混ぜない。** 3つのツールの出力は、それぞれ独立させる。
  - cf2v のノード(変数)を cf2f の図に合わせて整形したり、両方を1つの図にまとめる仕組みは持たない。まとめたい場合は、利用者が出力を連結する。
- **関数名を値として渡した場合は、呼び出しとして出力しない。** `sort(data, n, compare)` の `compare` は、呼び出しではないので辺にしない(GNU cflow は辺にする)。
- **出力は部分的な dot 形式にする。** `digraph{` と `}` は利用者が付ける。
  - 他のコマンドと組み合わせやすくするため。

### 未決

- メンバ呼び出し(`p->fn()`、`s.fn2()`)を呼び出しとして出力し続けるか([#12](https://github.com/tokudiro/cf2f/issues/12))。
- 壊れた入力(余分な `}` など)をどこまで許容するか。意図して設計した方針ではない。現状は、深さが 0 より小さくならないようにしているだけ。

## ツール

3つのツールは `src/main.c` と `src/SBuf.c` を共有する。`cf2f` と `funclist` は同じ `src/cf2f.l` から作り(`funclist` は `-DFUNCLIST` で出力だけを切り替える)、`cf2v` だけが `src/cf2v.l` を使う。
いずれも、第1引数に C ソースファイル(省略時は標準入力)を取り、結果を標準出力に出す。ファイルを開けないときは、stderr にメッセージを出して終了コード 1 で終わる。

| ツール | 出力 | 出力の例 |
|---|---|---|
| `cf2f` | 関数の呼び出し関係と、関数定義の目印 | `"foo()" -> "bar()"`、`"foo()"[color=red];` |
| `funclist` | 定義された関数名の一覧 | `foo` |
| `cf2v` | 各関数内で使われている局所外の変数 | `"foo()" -> "counter"` |

- `"関数()"[color=red];` は、その関数がこのソースで定義されていることを示す(呼ばれるだけの関数と区別するため)。
- `cf2v` は `-DUSE_TYPE_BUFFER` でビルドされ、型を保持するバッファを追加で使う。
- `cf2v` の目的は、関数がどの局所外の変数(グローバル変数など)を触っているかを知ること。関数内の宣言は、局所と局所外を分けるためだけに読み、出力しない。

## 字句解析の共通ルール

- コメント(`/* */`、`//`)、文字列、文字リテラル、プリプロセッサ行(`#...`)は読み飛ばす。
- 波括弧の深さを数え、深さが 0 に戻ったときに、直前に見た関数名を関数の終わりとして出力する。
  - ただし、関数本体の `{` だけが対象。`struct` / `union` / `enum` の定義(`struct S {`)と、`= {` の初期化は、関数本体として扱わない。字句だけで判定する(`)` より前に `struct` などが現れる、または `=` が現れる場合は関数本体でない)。
- `#if` / `#ifdef` / `#ifndef` の時点の深さを覚え、`#else` / `#elif` ではその深さから数え直す([src/brace_depth.h](../src/brace_depth.h))。`#ifdef` で関数の頭を切り替えるのは正しい C なので、この対応は方針の範囲内。深さは 0 より小さくならない(上の未決を参照)。
- `if`、`while`、`for`、`switch`、`return`、`sizeof` などのキーワードは、関数呼び出しとして扱わない。

## 既知の制限

issue で管理している。

- 行コメントの行末の `\`(行継続)を考慮しない([#5](https://github.com/tokudiro/cf2f/issues/5))。
- 関数ポインタ経由の呼び出し(`(*fp)()`、`tbl[0]()`)は、呼び出し先がわからないので拾わない。
- マクロの呼び出しは、関数呼び出しと区別できない。
- cf2v は、キャストや `sizeof` の中の型名(`(MyType)x`)と、呼び出しなしで渡した関数名を、変数として出力することがある。
- cf2v は、配列の長さの式(`int a[n]`)と、`case` の式の中の単語を読み飛ばすため、そこでの変数の使用は拾わない。

関連ツールとの比較は [#6](https://github.com/tokudiro/cf2f/issues/6) を参照。

## テスト

```sh
make test
```

- `tests/<ツール名>/` に、入力 `*.c` と期待出力 `*.out` を置く。
- `tests/<ツール名>/xfail/` は、既知の不具合の入力。失敗しても全体は失敗にならない。直って通るようになったら、通常のテストに移す。
- 実行は [tests/run.sh](../tests/run.sh)。
